# Corpus documents carve-rb's tree does not reproduce, and the pin that explains it.
#
# `npm run ast:check` compares carve-rb's tree against carve-rs's and gates on
# any difference: a binding serializes carve-rs's tree, so it has no vote of its
# own and there is no window in which it is the one that is right.
#
# That is true of the BINDING and not of the PIN.
# `carve-rb/ext/carve/Cargo.toml` names a PUBLISHED crate by org policy, and the
# AST conformance job builds carve-rs from MAIN, so between a merge and a
# release the two are supposed to differ and there is nowhere for the pin to
# move. "Bump it" is unactionable advice in that state
# (markup-carve/carve-rb#142, markup-carve/carve-rb#143, carve#2175).
#
# So the window is DECLARED, per document, and refused the moment it stops
# describing the world. `bindingParityProblems` (scripts/lib/binding-parity.mjs)
# reports each direction:
#
#   - the pin caught up (pinned === built)  -> the window is closed and every
#     row is a row about nothing. Delete the file.
#   - the pin MOVED but still lags          -> every row names the pin it was
#     measured against, so each row fails on its own line. Re-measure against
#     the new pin; do not repoint the text.
#   - a document drifts and is not listed   -> a gap in the BINDING, which no
#     pin explains. Red immediately, which is the point.
#   - a listed document reproduces again    -> the window moved past it; delete
#     the row.
#
# THE EXPIRY IS IN THE ROW, not in this header, because a header is not read by
# anything. Each reason names `=0.1.6`, the version carve-rb pins today. When
# carve-rs publishes 0.1.7 and carve-rb bumps to it, every row here fails until
# the file is deleted - which is the loud ending this window needs, the quiet one
# being a permanent declaration nobody re-measures.
#
# HOW THE MEASUREMENT WAS TAKEN. In the pull request that took it, not here.
#
# Format: <document>  <reason>
