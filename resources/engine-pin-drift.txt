# Corpus documents the PINNED reference build does not reproduce.
#
# `npm run engine:report` renders every corpus document through the
# `@markup-carve/carve` build package.json pins, and compares against the
# committed HTML. A mismatch is not automatically wrong: when a spec rule
# lands here, the engine has not shipped it yet, and the corpus is ahead of
# the pin until someone moves it. That window is normal and the report exists
# to describe it.
#
# What is NOT normal is not knowing which window you are in. carve#533 found
# the pinned build three documents behind with nothing reporting it, because
# `engine:report` was an npm script that no CI job ran.
#
# So the window is DECLARED rather than tolerated. This file lists the slugs
# the pin is knowingly behind on, one per line, each with the reason.
# `npm run engine:report -- --check` fails when the real set differs in
# EITHER direction:
#
#   - a slug mismatches and is not listed  -> new drift, or a corpus fixture
#     that does not match any engine. Red immediately, which is the point.
#   - a slug is listed and now reproduces  -> the pin moved past it. Delete
#     the line in the same commit that moves the pin.
#
# Emptying this file is the normal end state after `npm run bump-carve-pin`.
#
# Format: <slug><space><space><reason>
344-a-comment-only-line-in-a-line-block-is-removed-before-any-inline-run  carve#1333: the pin removes a comment-only verse line at the INLINE layer, so an unclosed verbatim run opened on an earlier line claims it first and the comment text is published inside the code span. PART 9 section 23 now says the removal is a block-layer step. The no-run control beside this case (-2) already reproduces, which is what makes the pair discriminating.
347-a-comment-fence-reached-through-a-quote-registers-nothing-either  markup-carve/carve-js#1177: the pin registers a link reference definition written inside a QUOTED comment fence, so the use below resolves instead of staying literal. carve#1309 ruled the definition is not registered wherever the fence sits, and this is the third column it can sit at. The FOOTNOTE kind beside this case (-2) already reproduces, which is what makes the pair discriminating: the leak sorts definitions by kind, so a single-kind fixture would let this build pass on the half it gets right. The no-fence control (-3) reproduces too.
348-a-closed-inline-construct-spanning-a-verse-boundary  carve#1351: the pin leaves the boundary a BARE NEWLINE where a closed inline construct spans it, so an emphasized couplet loses the per-line layout the block exists to preserve. PART 9 section 23's AN INLINE CONSTRUCT IS NOT A DEPTH THE RULE STOPS AT is the fix: the subject is the soft break NODE, and the construct encloses one rather than consuming it.
348-a-closed-inline-construct-spanning-a-verse-boundary-3  carve#1351: the same rule where the construct closes before a further line, so the pin hardens the second boundary of one stanza and not the first. The verbatim control (-2) and the backslash control (-4) both reproduce, which is what makes the set discriminating: the pin gets the two shapes that leave no soft break right and only the shape that leaves one wrong.
348-a-closed-inline-construct-spanning-a-verse-boundary-5  carve#1351: the same rule with a preserved leading run on the second line, which is the shape an implementation that re-reads the construct's raw text loses the NBSPs on as well.
