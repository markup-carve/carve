# Where each obligation on a NORMATIVE page is stated in resources/spec/
#
# One row per RFC-2119 MUST / MUST NOT sentence on a page declared
# `normative: true`. Checked both ways by scripts/normative-page-audit.mjs: an
# obligation with no row fails, and a row matching no obligation fails. The text
# is the sentence's opening words, so rewording the opening forces the row to be
# touched in the same diff.
#
# WHAT A ROW MEANS, AND WHAT IT DOES NOT. A row names the clause a human read as
# the obligation's home; the audit verifies that clause EXISTS and nothing more.
# It cannot verify the clause says the same thing - measured on this page, the
# lexical overlap between a real obligation and its clause (0.50 to 1.00) and
# between an invented obligation and its best clause anywhere (0.33 to 0.60)
# OVERLAP, so no threshold separates them. What the ledger buys is that a NEW
# obligation cannot land without someone naming its home in the same diff.
#
# UNSTATED is a DECLARED GAP, not an exemption: the obligation is on the page
# and in no clause. That is exactly what carve#1995 was, and writing this ledger
# found six more of the same shape. WEAKER means the clause exists and states
# something weaker than the page does - I4 makes source-position remapping a
# SHOULD while the page writes MUST. Every run prints both.
#
# THE ANCHOR is how a row detects a clause that LOSES the obligation. It is a
# short distinctive phrase that must appear in the cited clause, compared with
# whitespace collapsed and case folded so the EBNF's hard wrapping and the
# page's capitalization cannot break it. Delete the sentence from the clause and
# the row goes red. `-` where there is no clause to anchor into.
#
# The anchor is also what makes WEAKER mechanical rather than a note: the row
# for source positions anchors on the clause's own SHOULD, so a clause that is
# later strengthened to MUST fails the row and forces the gap to be closed here.
#
#   <page> :: <clause | UNSTATED | WEAKER <clause>> :: <anchor | -> :: <opening words>
